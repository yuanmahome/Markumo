# 链接模板回填专项修复（2026-10-29）

## 复现与根因

用户确认的输入顺序是先输入 `[]()`，移动光标到方括号内填写 `11`，再到圆括号内填写 `111`。此前只覆盖顺序输入完整链接的测试不能证明此流程正确。

在修复前的本地浏览器测试中，同一真实按键流程得到 `[11](111\)`，与用户恢复记录及截图一致。空标签的 Markdown 链接没有可显示的文本节点，而 Live 此时仍持有字面的括号。为保持语义一致，源码桥将右括号转义；之后填字无法使已转义的源码成为链接。另有原生 DOM 事务绕过 `handleTextInput` 的输入路径，也需要在事务提交处校验。

## 修改边界

- `strongInputRule.ts`：只跟踪当前编辑器中新输入的空链接模板的两个位置与块 ID；随事务映射，不保留全文快照。填写后用 Markdown 解析器验证整个源码块与目标文档严格一致，才接受来源可证明的模板修正。普通原生 DOM 输入采用最小源码差异与整块复核。
- `MarkdownEditorController.ts`：复用现有局部源码编辑器并恢复原始光标偏移，避免填入第一个文字后光标跳出链接；组合输入提交后再完成转换。远端同步与销毁清除模板来源记录，延迟焦点操作检查焦点版本。
- `InlineSourceView.ts`：非空源码若解析为空标签则保留待修正草稿，避免空段落归一化静默吞掉内容。
- 不自动移除从磁盘或恢复草稿加载的反斜杠，不改变作者主动转义的文字，不引入定时 GC、WebView 重启或额外文档副本。
