# 行内格式的 Typora 对照与验收

2026-10-30，v1.1.7，针对 v1.1.5 后用户补充的输入和删除场景。v1.1.6 在发布前 CI 检查中取消，未公开安装包。

## 实际对照

在本机 Typora 新建临时文档，输入 `**爱神的箭**`。光标停在格式末尾时，星号仍显示为淡色，正文同时加粗。选中 `爱神的箭**` 并删除后，剩余 `**` 是普通可编辑文本；再删除成 `*` 也没有警告，可以继续输入或换行。

另实测 ``*斜体* ~~删除线~~ `代码` ***粗斜体***`` 的连续输入：只有光标所在的格式显示标记，离开或换行后收起标记。

## 修复范围

- 局部格式使用行内语法解析，允许 `*`、`**`、`***` 等未闭合标记作为真实源码应用。通过替换原有行内范围并比较整个原始块，校验周围结构未被改变。
- 单独的 `*` 在重新加载时也作为未完成的行内文本显示，避免切换源码模式后变成不可见的空列表。
- 逐字输入完成后显示完整标记，光标位于闭合符号之后。整段输入与智能粘贴也执行同样的展示处理；这条路径原先已经生成格式节点，不会经过逐字输入规则。
- 光标输入到格式范围外或移到别处后，恢复折叠展示。保留空链接标签等真正未应用草稿的原有保护。
- 自动展示只跟随当前输入新引入的格式，不在替换已有格式文本的第一个字符后把光标移到闭合标记之外。补充八种已有格式中逐字替换的回归，包括行内代码中的链接文本。

## 自动验证

`node tests/phase042/inline-formatting-edit.mjs` 覆盖 `**`、`__`、`*`、`_`、`***`、`___`、`~~` 和反引号：活动标记、实际显示样式、精确选择删除、部分删除、继续输入、撤销重做、粘贴、格式内外移动、源码模式往返，以及标题、引用、列表、表格、实体和 LF/CRLF 保存。中文组合事件由自动测试模拟。

类型检查、生产构建、原生构建，以及行内规则、加粗输入、局部恢复、链接交互、链接输入、无损文档、空行持久化、资源生命周期与智能剪贴板回归通过。

## Windows 原生验证

构建独立应用标识和数据目录的 Windows Release 测试程序。输入、光标移动、选择、删除、换行和保存均通过 computer-use 执行；只读调试观察用于确认最终源码、未应用状态和警告状态，没有代替实际键盘输入。

原生操作验证完整顺序：输入 `**爱神的箭**` 后显示完整星号；选中 `爱神的箭**` 并删除；再删除一个星号；输入 `继续编辑`；移到下一段；输入斜体、删除线、代码和粗斜体；换行并保存。最终无未应用草稿、无组合输入阻塞、无警告，磁盘源码与编辑器源码一致。原生整段输入本次经过智能粘贴路径；逐字输入另由浏览器真实键盘回归覆盖。

原生临时文档和只读状态记录位于忽略跟踪的 `test-results/inline-formatting-debug.md` 与 `test-results/inline-formatting-native-final-state.json`。
