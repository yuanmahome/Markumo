# 统计偏好原生保存与更新准备修复

基线：main / v1.2.6，`e557c6f1cc5af86985ecbe58eea6139f34093f1e`。

前端 `persistedSettings()` 每次发送完整设置，已包含 `primaryStatistic`；Rust `EditorSettings` 使用 `deny_unknown_fields`，却没有该字段。Tauri 在命令反序列化阶段拒绝保存，所以不只统计偏好，其他首选项保存、安装前严格持久化及退出前设置保存都会受影响。既有浏览器统计回归只检查前端归一化和组件状态，未验证真实原生保存契约。本问题也存在于已发布的 1.2.6，不能归因于用户设置损坏或更新下载失败。

修复只补齐原生字段，默认 `words`，验证与前端一致的五个取值。继续保留未知字段/类型和设置预算校验、原子写入、失败保留旧文件及更新前严格保存，不通过忽略错误或删除字段绕过安装检查。

`tests/settings/default-settings.json` 由真实前端 `persistedSettings(defaultSettings())` 生成。新增浏览器测试对照完整快照并检查五项偏好保存和加载；Rust 使用相同快照反序列化、验证、实际写盘重读，并核对所有字段。两侧契约测试都加入 CI，避免前端新增字段后仅浏览器测试通过、原生命令失败。

Windows 原生验证使用独立安装名、配置和 WebView 数据目录，原测试包复现完全相同的未知字段拒绝，原设置字节不变。修复包通过测试专用引用访问真实 `useShellPreferences.flushSettings(true)` 和 `useAppShell.prepareUpdate()`，实际调用 Rust 设置、更新租约及会话持久化命令；不执行用户安装、重启或覆盖用户文档。非法统计值必须阻止准备、释放编辑锁，恢复有效值后可重新准备。

第一个修复测试构建曾把探针放在 Shell 初始化过早的位置，触发测试构建的变量初始化问题；失败记录保留。随后将探针移到 Shell 最终返回前，重新构建验证。该探针不进入生产应用。

旧版进程的代码无法由尚未启动的新版安装包修复。因此受影响用户需要保存全部文档、退出旧版后手动安装补丁一次；不建议清空设置或跳过未保存文档检查。

验证结果：

- 前端设置契约及持久化回归、既有统计组件回归、类型检查通过；Rust 全部 74/74 通过。
- Windows 隔离 NSIS 安装版 `settings-fix2-20261109` 8 项检查通过：五种主统计实际严格保存/磁盘重读、失败准备解锁、恢复有效设置后的原生更新租约与设置/会话严格持久化重试、应用重启恢复。该测试构建在版本递增前仍标识为 1.2.6，Rust/前端修复代码与后续 1.2.7 相同；不冒充已执行实际用户安装或四平台交互验收。
- 生产前端未添加兼容性删字段重试，`prepareInstallation` 和 `UpdateManager` 未放宽错误处理。

修复和安装版验证完成后，沿用用户本次发布要求，将版本字段同步递增为 1.2.7，通过远程 Quality Gate 后按既有四平台流程发布补丁。已公开的 1.2.6 安装包和标签保持原样。

版本递增后 `pnpm check`、设置浏览器契约测试、`cargo check --locked` 和 Rust 74/74 再次通过。原生成功、探针失败及修正记录、构建身份、最终构建检查日志见 [验证清单](statistics-settings-20261109/validation.json)，每份 gzip 附带原始字节 SHA-256。
