# Markdown 局部编辑恢复验收

2026-10-30，v1.1.5。

删除末尾 `***文字***` 的全部内容后，原实现仍保留零宽局部编辑器；空段落的换行处理可能移动源码边界，使继续输入使用过期范围。修复后，删除完成即退出局部编辑，并在成功应用修改后才更新桥接文档与局部坐标。

另复现了未应用草稿阻挡撤销后的正文同步。撤销现在先取消未应用草稿；正文焦点也支持按 Esc 退出该状态。

`node tests/phase042/inline-source-recovery.mjs` 覆盖逐字、选中与向前删除，继续输入，草稿撤销，正文焦点 Esc，局部发布异常后重试，结构变化后的撤销，以及 LF/CRLF 和不同末尾空行。

截图中的 `Position 316 out of range` 尚未通过自然输入稳定复现。该测试注入一次同类异常，检查失败后正文、桥接文档与局部范围保持原值，并验证后续重试成功；不将异常注入视为原始越界触发的复现。

前期检查通过类型检查、生产构建、链接交互、链接输入、行内 Markdown、无损 Markdown 与空行持久化回归。`table-image-boundaries.mjs` 在图片后按 Enter 的用例中出现额外空行；通过 Vite 在内存加载未修改的 HEAD 源码确认同一断言也失败，属于已存在的问题，本次未改动该行为。
